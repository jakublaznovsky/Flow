# Flow v0.2 — Design Spec

Date: 2026-11-04
Builds on: `2026-11-03-flow-design.md` (v1). Everything there still holds unless changed here.
Status: decided autonomously (owner asked: "work independently"; clean modern UI, simple,
many useful functions for focusing on projects and progressing work).

## 1. Goals

- Make it easy to **focus on one project** and see its goal, notes and progress.
- Make **progress visible** (week, year, per project), which motivates (ADHD-friendly).
- Help **staying on one task** with a quiet focus timer.
- Keep it **simple**: one window, a sidebar, two views (Board, Progress). Still no warnings,
  nags or pop-ups; the timer ending is a quiet inline state.
- Stay **AI-friendly**: new data (focus sessions, notes, decisions) lives in the same Markdown
  files; a "Copy AI review" button prepares a ready-to-paste prompt.

## 2. Data format changes

### 2.1 Day file — new optional `focus` list

```yaml
focus:
  - ref: flow-app/t2
    title: Set up Tauri project
    project: Flow app
    minutes: 25
```

- One entry per finished or stopped focus session (sessions shorter than 1 minute are not logged).
- Snapshot of title/project like `done`. Unknown fields on entries preserved.
- Omitted from the file when empty, so v1 files are unchanged on write.

### 2.2 Project file

- `goal` becomes editable in the app (empty → field removed).
- Body (notes) editable in the app as plain text.
- "Add decision" appends `- YYYY-MM-DD: <text>` as the last item of the `## Decisions`
  section in the body (the section is created at the end of the body if missing).

`README_TEXT` (written into new Flow folders) documents the `focus` field.

## 3. UI

### 3.1 Layout

```
┌──────────────┬──────────────────────────────────────────────┐
│ Flow         │ [project header when focused]   [search  /]  │
│              ├──────────────────────────────────────────────┤
│ ▣ Board      │ [focus bar when a timer runs]                │
│ ◔ Progress   │                                              │
│              │  Parking lot │ To do │ Today │ Done          │
│ PROJECTS     │                                              │
│ ● All        │      (or the Progress view)                  │
│ ● Flow app ▬ │                                              │
│ ● Spanish  ▬ │                                              │
│ Hidden (1)   │                                              │
│ + New project│                                              │
│              │                                              │
│ Ctrl+Shift+  │                                              │
│ Space capture│                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- **Sidebar** (fixed, ~240px): app name, view switch (Board, Progress), project list. Each
  project row shows a color dot, title and a thin progress bar (done/total tasks), and a "⋯"
  button (also right-click) with Rename, Color, Pause, Mark done, Archive. "Hidden (N)" lists
  non-active projects with "Make active". "+ New project" inline input.
- Clicking a project **focuses** it (same as the v1 filter); "All projects" clears it.
- **Design:** clean and modern. CSS custom-property tokens; light and dark theme following the
  OS (`prefers-color-scheme`); system UI font stack; neutral surfaces, one accent color,
  rounded corners (8–12px), soft shadows, generous spacing, subtle hover states, visible focus
  rings, no heavy borders. Cards show a thin left stripe in the project color. Column headers
  show a count. Empty columns show a soft placeholder.

### 3.2 Project focus header

When a project is focused, above the board: project title, goal (click to edit inline),
progress bar with "X of Y done", "Done this week: N", and a **Notes** button that opens a
right-side panel: a textarea with the project notes (body; saved on blur or Save) and an
"Add decision" input (Enter adds).

### 3.3 Search and shortcuts

- Search field in the top bar filters visible cards (title, first step, project title;
  case-insensitive). Escape in the field clears it.
- Shortcuts when no text field is focused: `/` focuses search, `n` opens "New task" in To do,
  `b` Board view, `p` Progress view, `o` Notes view, `w` Week view, `r` Weekly review.

### 3.4 Focus timer

- Today cards have a "Focus" button. It starts a session (default 25 min; the focus bar offers
  15 / 25 / 45 before or while running — changing it restarts the countdown length).
- The **focus bar** (top of the main area) shows the task title, mm:ss remaining, Pause/Resume
  and Stop. Only one session at a time; starting another replaces it (the old one is logged if
  ≥1 min).
- At 0:00 the bar quietly changes to "Session done · 25 min" with **Mark done** (moves the task
  to Done), **Another round**, and **Close**. No sound, no pop-up, no window flashing.
- Stop logs the elapsed whole minutes if ≥1. Each session is logged once.
- Timer state lives in memory only (closing the app ends the session; nothing logged).

### 3.5 Progress view

- **No streaks** (owner decision 2026-11-04): nothing in Flow counts consecutive days.
- **This week:** Monday–Sunday columns of the current week, each listing that day's completed
  tasks (from day files) and focus minutes. Today highlighted.
- **Year:** heatmap of the last 53 weeks (Monday-first columns), cell shade by completed count
  (0, 1, 2–3, 4–5, 6+); future days blank; hover title "YYYY-MM-DD: N done".
- **Projects:** each active project with progress bar (done/total) and "N done in last 7 days".
- **Today's note:** textarea bound to today's day file body (saved on blur).
- **Copy AI review:** copies a prompt to the clipboard: instructions to give honest, kind
  feedback and suggest the next 3 days' plan, followed by the last 7 days (done tasks per day,
  focus minutes, notes) and active projects with goals and open tasks. Button shows "Copied" for
  2 s. If the clipboard is unavailable the text is shown in a read-only textarea to copy by hand.

### 3.6 Notes view (owner request 2026-11-04: "some space for the notes")

- Third sidebar view **Notes** (shortcut `o`), next to Board and Progress.
- Two panes: a list on the left — **General notes** first, then each active project — and a
  large, calm editor (textarea, comfortable line length, generous padding) on the right for the
  selected item. Saved on blur and when switching items; no Save dialog, no warnings.
- General notes are stored in a new file `Flow/notes.md` (plain Markdown; optional frontmatter
  preserved). Created on first save; a missing file means empty notes.
- Project notes are the project file body (the same text as the project Notes panel, §3.2).
- The editor shows a muted line with where the text is stored (e.g. `notes.md`,
  `projects/flow-app.md`), so the owner knows what an AI will read.
- "Copy AI review" (§3.5) also includes General notes (truncated to 2,000 characters).

### 3.7 Checklist inside a task (owner request 2026-11-04)

- A task can hold **steps**: `steps: [{text, done}]` in the project file (omitted when empty;
  unknown fields on steps preserved).
- Card shows a small `2/5` pill when steps exist, and the first unchecked step as a muted
  "Next: …" line. A chevron expands the card into the checklist: checkboxes, inline "Add step"
  input (Enter adds, stays open for the next), delete ×, and edit by clicking the text.
- The focus bar shows the task's next unchecked step under the title.
- Ticking the last step does not complete the task automatically (no surprises); the task
  checkbox stays the way to finish.

### 3.8 Plan the week (owner request 2026-11-04)

- A task can be **scheduled** for a day: `scheduled: YYYY-MM-DD` in the project file.
- New sidebar view **Week** (shortcut `w`): seven day columns Mon–Sun for a week with
  previous / next / "This week" navigation, plus an **Unscheduled** tray listing To do tasks
  without a date. Each day column lists tasks scheduled for that day and, muted, the tasks
  completed that day (from day files). Today's column is highlighted; past days are read-only
  (can't drop onto them).
- Drag a card onto a future day → scheduled for that day; onto Today's column → moved straight
  to Today; onto Unscheduled → date cleared. The card edit form also has a "Plan for" date field.
- **On that day it shows up in Today by itself:** whenever Flow loads or the date changes, every
  To do task with `scheduled ≤ today` moves to Today (same bookkeeping as a manual move) and its
  `scheduled` field is cleared. Board cards show a small day chip ("Thu 6") when scheduled.
- Respects the project focus filter.

### 3.9 Weekly review (owner request 2026-11-04)

- Sidebar item **Weekly review** (shortcut `r`) opens a guided 4-step flow; any time, no
  reminders or nudges.
  1. **Your week** — completed tasks per day and total focus minutes for the current week.
  2. **Unfinished** — tasks in Today and tasks scheduled this week that are not done. Each row:
     *Keep in Today*, *Next week* (schedules next Monday), *Back to To do*, *Delete*.
  3. **Next week's focus** — pick one active project (optional) and write a one-line intention.
  4. **Reflect** — free text, plus "Copy AI review" and, if AI is set up, "Ask Claude".
- Saved to `reviews/YYYY-Www.md` (ISO week, e.g. `reviews/2026-W45.md`) with frontmatter
  `week`, `focus_project` (slug, optional), `intention` (optional) and the reflection as body.
  Re-opening the review for the same week edits that file.
- The chosen focus project is marked with a ★ in the sidebar for that week (shown while the
  current ISO week's review names it).

### 3.10 AI built in (owner request 2026-11-04)

- **Settings** (gear at the bottom of the sidebar, shortcut none): Claude API key (password
  field; Save / Remove) and model (Claude Opus 5.5 — default, Claude Sonnet 5.5, Claude Haiku 5.5).
  Stored in the app's local settings (`anthropicApiKey`, `aiModel`), never in the Flow folder.
  A muted line explains that the key stays on this computer and that pressing an AI button sends
  the shown Flow data to Anthropic.
- **Review my week** — sends the §3.5 review prompt; the answer streams into an **AI panel**
  (right drawer) as readable text (headings, lists, paragraphs). Buttons: Copy, Save to notes
  (appends `## Claude review YYYY-MM-DD` + text to General notes), Close.
- **Plan tomorrow** — sends a planning prompt (last 3 days, open tasks with refs, scheduled
  tasks, this week's focus project and intention) and asks for structured JSON: a short summary
  and up to 3 suggested tasks `{ref?, title, project, first_step}`. The panel lists them with
  **Add to tomorrow** (existing ref → scheduled for tomorrow; new → created in that project with
  the first step, scheduled for tomorrow) and **Add all**.
- Buttons live in the Progress view and in step 4 of the weekly review. Without a key they read
  "Set up Claude in Settings" and open Settings.
- Errors are shown as one calm line inside the AI panel (e.g. "Claude didn't accept the API key —
  check it in Settings."), never as a pop-up.
- Implementation: official TypeScript SDK `@anthropic-ai/sdk` in the webview
  (`dangerouslyAllowBrowser: true`, user-supplied key). Default model `claude-opus-5-5`, effort
  `medium`, server-side `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`) for Opus
  5.5 / Sonnet 5.5; handle `stop_reason: "refusal"`. Review streams; plan uses
  `output_config.format` JSON schema. Typed SDK error classes.

## 4. Architecture

- New pure model modules: `src/model/focus.ts` (logging), `src/model/stats.ts` (week, heatmap,
  project progress), `src/model/review.ts` (prompt text); date helpers in `dates.ts`.
- `Board.tsx` stays the top-level component (same props and exports); board columns move to
  `BoardView.tsx`; new `Sidebar.tsx` (replaces `ProjectBar.tsx`), `ProjectHeader.tsx`,
  `NotesPanel.tsx`, `FocusBar.tsx` + `useFocus.ts`, `ProgressView.tsx`, `SearchBox.tsx`;
  `theme.css` holds tokens.
- No new dependencies unless clearly needed. No Tauri code changes needed.

## 5. Testing

Model functions unit-tested; UI behaviors tested with RTL + MemoryFileStore; focus timer with
fake timers; smoke test updated (Board and Progress screenshots, light and dark).
