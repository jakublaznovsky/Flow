# Flow Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Flow v1 — a Tauri desktop app showing one four-column task board (Parking lot / To do / Today / Done) backed by a folder of Markdown files.

**Architecture:** Pure TypeScript model functions (`src/model/`) transform an in-memory `FlowData`; `src/storage/` parses/serializes Markdown+YAML files and talks to a minimal `FileStore` interface (in-memory for tests and browser dev, Tauri fs for the desktop app); React UI (`src/ui/`) holds state and saves changed files. Rust only registers Tauri plugins.

**Tech Stack:** Tauri 2 (`@tauri-apps/cli` 2.x), React 19 + TypeScript + Vite, Vitest + React Testing Library + jsdom, `yaml` for frontmatter, `@dnd-kit/core` + `@dnd-kit/sortable` for drag and drop, Tauri plugins `fs` (with `watch` feature), `dialog`, `global-shortcut`, `store`.

**Spec:** `docs/superpowers/specs/2026-11-03-flow-design.md`

## Global Constraints

- Data folder layout exactly as spec §2: `README.md`, `inbox.md`, `projects/<slug>.md`, `days/YYYY-MM-DD.md`, `flow-issues.log`.
- Dates are ISO `YYYY-MM-DD` in **local** time (never `toISOString().slice(0,10)`).
- Project `status`: `active | paused | done | archived`. Task `status`: `todo | today | done`.
- Task ids `t1, t2, …` unique per project; global ref `<slug>/<id>`. Inbox ids `i1, i2, …`.
- Slug derived from title once at creation and never changed on rename.
- Flow never shows warnings, nags, or pop-ups. Problems go only to `Flow/flow-issues.log`.
- A file that failed to parse is never written by Flow.
- Unknown frontmatter fields and the Markdown body of every file are preserved on write.
- Empty Today column hint text: `pick up to 3`. No warning when Today has more than 3.
- Quick capture shortcut: `CommandOrControl+Shift+Space`.
- All app logic in TypeScript; Rust is plugin registration only.

## Review Focus

1. **Broken file then an action that writes it** (e.g. today's day file was hand-edited into invalid YAML, then a task is completed) → file left untouched, issue logged, app keeps working. Test in Task 6.
2. **AI/text-editor edits with extra fields or prose** → unknown frontmatter keys and body survive a Flow save byte-for-byte in meaning. Test in Task 3.
3. **Project titles that collide or have diacritics/emoji** (`Učit se španělsky`, two projects named `Work`, `🚀`) → slugs `ucit-se-spanelsky`, `work-2`, `project`. Test in Task 2.
4. **Midnight / local date** → at 23:30 local in a UTC+ zone, "today" is the local date; Done column empties after the date changes while the app is open. Tests in Tasks 2 and 7.
5. **Hand-added tasks missing `id`, `status`, or with duplicate ids** → loaded as `todo` with fresh unique ids, no crash. Test in Task 3.

```ts
// fileStore.ts — paths are relative to the Flow folder, '/' separated
export interface FileStore {
  list(dir: string): Promise<string[]>;                  // file names in dir; [] if dir missing
  read(path: string): Promise<string | null>;            // null if missing
  write(path: string, text: string): Promise<void>;      // atomic, creates parent dirs
  append(path: string, text: string): Promise<void>;
  watch(onChange: (paths: string[]) => void): Promise<() => void>; // only external changes
}
export class MemoryFileStore implements FileStore {
  constructor(initial?: Record<string, string>);
  files: Record<string, string>;                         // inspectable in tests
  externalWrite(path: string, text: string): void;       // simulates an editor/AI edit; fires watchers
}
// flowRepo.ts
export async function ensureFolder(store: FileStore): Promise<void>;   // writes README.md and inbox.md if missing
export async function loadFlow(store: FileStore, today: ISODate): Promise<FlowData>;
export async function reloadPaths(store: FileStore, d: FlowData, paths: string[], today: ISODate): Promise<FlowData>;
export async function saveFlow(store: FileStore, d: FlowData, changed: string[]): Promise<void>;
export async function logIssue(store: FileStore, path: string, reason: string, now?: Date): Promise<void>;
export const README_TEXT: string;
```
- `loadFlow`: reads `inbox.md`, every `projects/*.md`, every `days/*.md` (ignore other names and `*.tmp`). A parse failure → path added to `skipped`, `logIssue` called, load continues.
- `saveFlow`: for each changed path, serialize from `d` and write; **if the path is in `d.skipped`, do not write it and call `logIssue(path, 'not saved: file could not be read')`**. A write that throws is retried once, then logged; never throws to the caller.
- `logIssue` appends `` `${now.toISOString()}  ${path}  ${reason}\n` `` to `flow-issues.log`.
- `reloadPaths`: re-parses only the given paths (removing from `skipped` on success, adding on failure; deleted files are removed from `d`).
- `README_TEXT`: explains the folder layout, every field of the three file types (copy the field comments from spec §2), and two example prompts: `Read the files in Flow/days from the last 7 days and give me honest feedback on my week.` and `Look at my active projects in Flow/projects and suggest what I should plan for tomorrow.`
